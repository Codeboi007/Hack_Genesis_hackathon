# Repository

## Overview
A full-stack application providing a backend API for repository analysis, automated multi-agent code reviews, and documentation generation. The system parses source code to build dependency graphs and uses retrieval-augmented generation (RAG) to ground AI analysis.

**Surface Metrics:** 66 files, 197 functions, 45 classes.

## Architecture / How It Works
The system processes repositories through the following pipeline:
1. **Ingestion**: `backend/services/ingestion.py normalizes repository input (URL/ZIP) into a workspace.
2. **Parsing**: `docs/repo_loader.py` and `docs/parser.py` discover and parse source files.
3. **Indexing**: `rag/rag_pipeline.py` indexes parsed content for retrieval-assisted generation.
4. **Analysis**: Multi-agent analysis is orchestrated by `agents/orchestrator.py`, utilizing specialized agents (e.g., `ArchitectureAgent` in `agents/architecture_agent.py`).
5. **GitHub Integration**: `github/webhook.py` validates signatures and triggers `github/pr_handler.py`, which uses `github/diff_fetcher.py` to retrieve PR diffs and `github/commenter.py` to post reviews.
6. **Output**: `backend/services/doc_service.py` assembles documentation, including READMEs and graphs generated by `docs/graph_builder.py`.

## Project Structure
```text
agents/             # AI analysis agents (architecture, bug, performance, etc.)
backend/            # FastAPI service, business logic, and RAG integration
components/         # Shared UI components (GraphView, TreeView)
docs/               # Repository analysis, AST parsing, and graph construction
frontend/           # Next.js dashboard and visualization interface
github/             # GitHub API interactions, webhooks, and PR handling
rag/                # Vector store, embedding, and chunking pipeline
utils/              # Shared utilities and graph adapters
```

## Key Components
- **`github/`**: 
    - `diff_fetcher.py`: Contains `fetch_pr_diff` and `parse_unified_diff`.
    - `webhook.py`: Implements `validate_github_signature`.
    - `pr_handler.py`: Implements `build_virtual_files_from_diff`.
    - `commenter.py`: Handles `post_pr_review` and `format_inline_comments`.
- **`docs/`**:
    - `repo_loader.py`: Provides `iter_code_files` and `read_text_safe`.
    - `graph_builder.py`: Implements `build_dependency_graph` and `build_execution_flowchart`.
    - `rot_detector.py`: Contains `detect_doc_rot`.
- **`agents/`**:
    - `architecture_agent.py`: Implements `ArchitectureAgent`.
    - `orchestrator.py`: Manages the execution flow of analysis agents.
- **`backend/services/`**:
    - `ingestion.py`: Manages workspace creation and cleanup.
    - `nim_client.py`: Implements `RatePacer` and `get_nim_client` for LLM interactions.
    - `doc_service.py`: Implements `DocumentationService` for modular doc generation.

## Technologies Used
- **Backend**: Python, FastAPI, Pydantic, Redis, httpx, requests, PyJWT.
- **Frontend**: TypeScript, React, Next.js.
- **Data/AI**: RAG pipeline, Vector Store.

## Usage
```bash
# Backend setup
python -m venv .venv
source .venv/bin/activate
pip install -r backend/requirements.txt
uvicorn backend.main:app --host 0.0.0.0 --port 8000

# Frontend setup
cd frontend
npm install
npm run dev
```

## Notes / Limitations
- **Coupling**: There is tight coupling between `github.pr_handler` and `docs.parser`.
- **Performance**: `docs.graph_builder` may encounter bottlenecks during large repository analysis due to recursive node/edge deduplication.
- **I/O**: `github.commenter` and `github.diff_fetcher` rely on synchronous `requests` calls, which may timeout on large PRs.
